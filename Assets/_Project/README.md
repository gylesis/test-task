# Top-Down Survivor — тестовое задание

3D-выживание с видом сверху: игрок автоматически стреляет по ближайшему врагу,
орды врагов идут к нему и бьют вплотную. Задача — продержаться как можно дольше.

**Платформа:** Android, ландшафтная ориентация.
**Точка входа:** сцена `Assets/_Project/Scenes/Bootstrap.unity`.

# Меню конфигов, где можно менять параметры
`Tools → Game → Configs` 

## Как добавить нового врага

### 1. Модель

Взять готовый humanoid-префаб (например из `ToonyTinyPeople`) и сделать его вариант
в `Prefabs/Models`. Внутри варианта:

- на `Animator` поставить нужный `AnimatorController` из `Assets/_Project/Animators`;
- **для стрелка** — найти в иерархии кость оружия (у полицейского это `w_handgun`),
  создать внутри неё пустышку `MuzzlePoint`, повесить на неё одноимённый компонент
  и отодвинуть по локальной Z до конца ствола. Из этой точки летит пуля и вспышка;
- **для рэгдолла** — повесить на корень модели компонент `Ragdoll`, а на кости
  (`Hips`, `Spine`, `Head`, руки, ноги) — `Rigidbody`, коллайдеры и `CharacterJoint`.
  Быстрее всего это делает штатный `GameObject → 3D Object → Ragdoll`.
  Все кости положить на слой `Ragdoll` — иначе трупы будут толкать живых врагов,
  а пули врезаться в тело вместо пролёта.

### 2. Префаб врага

Сделать вариант `Prefabs/Enemy_Base` в папке `Prefabs/Enemies`, положить модель
внутрь `ModelRoot` и проставить ссылки в `EnemyController`:

| Поле | Что положить |
|---|---|
| `Model` | объект модели внутри `ModelRoot` |
| `Muzzle Point` | `MuzzlePoint` из модели (только для `Ranged`) |
| `Ragdoll` | компонент `Ragdoll` с корня модели |
| `Health View`, `Hit Collider`, `Animator View`, `Hit Flash` | уже проставлены в `Enemy_Base` |

В `Enemy Animator View` на корне префаба указать `Animator` из модели.

### 3. Конфиг

`Create → Game → Enemy Config` в `Configs/Enemies`, либо через
`Tools → Game → Configs → + Новый враг` — второй способ сразу добавит врага в спавнер.

Заполнить `Prefab` (созданный на шаге 2) и параметры из ТЗ:
здоровье, скорость, урон. Для `Attack Type = Ranged` откроется блок «Дальний бой»:

| Поле | Смысл |
|---|---|
| `Keep Distance` | ближе этой дистанции враг пятится, продолжая стрелять |
| `Attack Range` | дальность, с которой открывает огонь |
| `Projectile Prefab` | снаряд, например `Prefabs/Projectile_Enemy` |
| `Projectile Speed` / `Lifetime` / `Radius` | параметры полёта |
| `Muzzle Height` | запасная высота выстрела, если `MuzzlePoint` не задан |
| `Hit Mask` | слой `Player` — по кому попадает снаряд |
| `Obstacle Mask` | слой `Obstacle` — обо что разбивается |
| `Retreat Speed Multiplier` | скорость отступления от `Move Speed` |
| `Aim Delay` | задержка перед первым выстрелом после сближения |

### 4. Спавнер

Добавить строку в `SpawnConfig → Enemies`: ссылка на конфиг и `Weight` —
вес в случайном выборе, чем больше, тем чаще появляется.

## Баланс

Все конфиги открываются одним окном: **`Tools → Game → Configs`** (`Ctrl+Shift+C`).
Слева список, сгруппированный на «Основные» и «Враги», с поиском; справа обычный инспектор
выбранного ассета. Правки применяются сразу, кнопка «Сохранить» пишет их на диск.

Диапазоны значений задаются структурой `MinMax` — в инспекторе она рисуется одной строкой,
`max` автоматически не опускается ниже `min`. Помимо `Roll()` (случайное значение в диапазоне)
у неё есть `Lerp`, `Clamp`, `Contains` и `Average`.

Где используется:

| Конфиг | Поле | Смысл |
|---|---|---|
| `WeaponConfig` | `Damage` | урон разыгрывается на каждом выстреле |
| `EnemyConfig` | `Damage` | то же для каждого врага |
| `SpawnConfig` | `Spawn Radius` | кольцо вокруг игрока, где появляются враги |

Что где лежит:

| Что | Где |
|---|---|
| Здоровье / скорость игрока | `PlayerConfig` |
| Скорострельность, урон, дальность, скорость пули | `WeaponConfig` |
| Минимум врагов на поле (по ТЗ — 5), максимум, темп спавна, радиус спавна | `SpawnConfig` |
| Нарастание сложности | `SpawnConfig → Extra Enemy Per Second` |
| Положение, плавность и обзор камеры | `CameraConfig` |
| Режим ввода и мёртвая зона | `InputConfig` |
| Эффекты попаданий и смерти | `VfxConfig` |
| Всплывающий урон: размер, подъём, цвет | `DamagePopupConfig` |
| Шторка загрузки и объём прогрева пулов | `SceneLoadingConfig` |
| Рэгдолл: импульс смерти, время до исчезновения | `EnemyConfig`, блок «Смерть» |
| Тряска камеры | компонент `CameraShake` на `MainCamera` |

## Камера

`CameraController` следует за игроком через `SmoothDamp` и держит фиксированный угол
из `CameraConfig → Fixed Rotation` — вращения по Y нет, вид сверху стабильный.

FOV в Unity вертикальный, поэтому при фиксированном значении горизонтальный обзор
менялся бы вместе с соотношением сторон: на планшете 4:3 игрок видел бы по бокам
почти на четверть меньше, чем на телефоне 20:9. Чтобы обзор был одинаковым,
`CameraController` пересчитывает FOV относительно `Reference Aspect` (16:9):
если экран уже эталона, вертикальный угол расширяется так, чтобы по горизонтали
влезало столько же. На широких экранах значение из конфига используется как есть.

Пересчёт идёт в `LateUpdate`, но только когда `aspect` реально изменился —
это покрывает и поворот устройства, и смену размера Game View в редакторе.

Тряска камеры живёт отдельно в `CameraShake`: она накладывает смещение поверх позиции,
посчитанной контроллером, и снимает его перед следующим кадром, чтобы `SmoothDamp`
не считал от потрясённой позиции. Контроллер про тряску ничего не знает.

## Управление

`InputConfig → Mode`:
- `Auto` — клавиатура на ПК, джойстик на мобиле;
- `Keyboard` — WASD / стрелки;
- `Joystick` — экранный джойстик.
